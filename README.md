I build and run infrastructure — clusters, the networks under them, and the hardware
under that. I work at Mirantis and live in Etobicoke, Ontario.

This account is where my work starts. Ideas begin here as scratch work, and the ones
worth keeping move on: to [LABSONLINE][labs] to be built out and hardened, and then to
[ANSELMES][org] when they are ready to be depended on. Most of what I build stays
private, so what is visible here is a small and largely incidental slice rather than a

## 1. 💼 What I work on

**At work.** Senior DevOps Engineer at Mirantis.

- **AI and GPU infrastructure at scale** — provisioning, scheduling, and operating
  accelerated compute for training and inference workloads
- **Kubernetes and cloud-native platforms** — cluster lifecycle, networking and
  storage, GitOps delivery, and the CI/CD around all of it
- **OpenStack**

**On my own time.** Roughly the same problems, one layer lower and with nobody to
answer to.

- **Bare metal and networking** — provisioning and PKI, routing and switching
- **Embedded and FPGA** — firmware and boards, and HDL work on SoC FPGA targets
- **Swift beyond the Mac** — Apple platforms, but also Swift on embedded targets and
  RTOS, which is the part I find genuinely interesting

## 5. 🤝 Issues and contributions

By default these repositories are read-only from the outside. They are published for
reference, contributions are not solicited, and no support commitment or response time
attaches to an issue or a pull request — this is work I maintain alongside a job.

That default is a floor rather than a ceiling. A repository carrying its own
`CONTRIBUTING.md`, or stating a policy in its README, supersedes what is written here,
so check the repository itself before assuming the default applies.

Forks are the exception throughout: changes to them belong upstream, with the project
that owns the code.

> [!CAUTION]
> Never report a security vulnerability in a public issue or pull request. Email
> <schubert@anselm.es> directly, or use GitHub's private vulnerability reporting on the
> repository concerned.
